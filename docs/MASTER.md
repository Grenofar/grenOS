# Instructions du Maître

## Consignes en vigueur
- Le build doit passer avec cargo build --release et zéro avertissement clippy.
- Produire une image bootable avec Limine qui affiche 'grenOS' sur le port série COM1 et s'arrête proprement.
- serial.rs defines pub fn write_hex(value: u64). idt.rs calls it and it does not exist yet.
- In idt.rs each IdtEntry offset field takes its own cast: with addr = handler as usize as u64, offset_low is (addr & 0xFFFF) as u16, offset_mid is ((addr >> 16) & 0xFFFF) as u16, offset_high is (addr >> 32) as u32.
- page_fault_handler prints CR2 and the error code with write_hex, then halts in a hlt loop. Returning re-runs the faulting read forever.
- In gdt.rs tss_base is already a u64: no as u64 on anything built from it, since clippy rejects a cast to the same type.
- In serial.rs write_hex: let nibble = ((value >> shift) & 0xF) as u8; then let c = if nibble < 10 { b'0' + nibble } else { b'A' + (nibble - 10) }; with no match.
- gdt.rs takes addresses with core::ptr::addr_of!(TSS), addr_of!(IST1_STACK) and addr_of!(GDT), never with &.
- gdt.rs sets the GDT limit to size_of::<[u64; 5]>() - 1, not GDT.len() * 8 - 1.
- gdt.rs drops as u64 on the tss_base expressions, already u64, and writes 0x89_u64.
- gdt.rs makes DescriptorTablePointer pub, since pub fn load_gdt takes it.
- idt.rs zeroes the table with for i in 0..256, not 0..IDT.len().
- The serial output shows grenOS, a Breakpoint line, then a Page fault line with CR2 and the error code, then the kernel halts; never panic, triple fault or double fault.
- For the desktop mission: implement a single Coder task that adds framebuffer driver and desktop rendering, meeting the following acceptance criteria:
  1. cargo build --release succeeds in kernel/
  2. cargo clippy --release -- -D warnings reports no warning in kernel/
  3. The kernel requests the framebuffer from Limine with a FramebufferRequest and draws to it.
  4. The Display struct (or equivalent) exposes width and height as pub fields or accessors, used by desktop.rs; private fields cause compile error E0616.
  5. All colour constants defined are used; unused constants like DARK_GRAY and BLACK are removed to avoid dead_code warnings.
  6. Window size and taskbar height are computed from framebuffer width and height: window roughly half screen in each dimension, taskbar about 40 px high, ensuring background colour covers less than 90% of screen.
  7. Text is drawn using an 8x8 bitmap font stored as a const table in the kernel: "grenOS" on the Start button, "12:00" on the right of the taskbar, "Bienvenue dans grenOS" inside the window.
  8. kmain no longer reads 0xffff_ffff_8020_0000; after int3 check it draws the desktop, writes a debug message to COM1, then halts.
  9. The resulting ISO boots in QEMU, prints "grenOS" on serial COM1, and the screen shows the desktop as described.
